# Security policy

Pico is early-stage software, not production-hardened. Security fixes target the latest `main`; older revisions and preview releases have no separate maintenance guarantee.

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/MirkoMignini/pico/security/advisories/new). Do not open a public issue for exploitable vulnerabilities or include credentials, personal data, private transcripts or unredacted logs.

Include the affected revision, platform, a minimal synthetic reproduction, the expected/actual security boundary and potential impact. Do not test against real owners or third-party services without authorization. No guaranteed response SLA or independent security certification is claimed.

Read the [security model and known dependency advisory](docs/SECURITY.md), [testing limits](docs/TESTING.md) and [deployment guidance](docs/DEPLOYMENT.md) before use.
